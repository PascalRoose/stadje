# Data Model: Automated Dependency Updates

## Update Policy

Repository metadata describing how Dependabot proposes changes.

| Field | Constraint |
| --- | --- |
| Ecosystem | npm for the pnpm project and github-actions for workflow actions |
| Directory | `/` for both configured ecosystems |
| Schedule | `weekly`; no daily or per-commit version-update schedule |
| Cooldown | `default-days: 2`, meaning a version must be at least 48 hours old |
| Grouping | Wildcard grouping where possible for each ecosystem |
| Open proposals | Maximum five version-update pull requests per ecosystem configuration |
| Labels | `dependencies` for generated pull requests |

## Dependency Update Proposal

A pull request generated by Dependabot.

| Attribute | Constraint |
| --- | --- |
| Package manifest | `package.json` may change for npm dependency updates |
| Lockfile | `pnpm-lock.yaml` must change with manifest version updates when resolution changes |
| Workflow references | `.github/workflows/*.yml` and `.github/workflows/*.yaml` action references are covered |
| Compatibility gate | Existing CI must pass on Node.js 24 before merge |
